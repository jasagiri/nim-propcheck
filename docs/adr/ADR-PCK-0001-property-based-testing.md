# ADR-PCK-0001: 性質にもとづくテスト — 種から値を生成し、反例を最小まで縮める

- **Status**: Accepted (下の仕様 ID を実装した)
- **Date**: 2026-10-07
- **関連**: ADR-MUTER-0004 (生き残りは仕様への問いである)、ADR-KURA-0008 (テストの分類)、ADR-KURA-0017 (仕様網羅と変異検出)

## 背景

テストの価値は、実装と独立した情報を持っているかで決まる (ADR-MUTER-0004)。例を 1 つずつ書くテストは、書き手が思いついた入力しか確かめない。AI に書かせると、入力は実装を読んで選ばれ、実装と独立した情報は増えない。

**性質**は、仕様から直接書ける。「行頭禁則の文字で始まる行は無い」「組み直しても総和は変わらない」「読み込んで書き出すと元に戻る」。入力は道具が生成し、性質が破れたら、破れる入力を最小まで縮めて示す。実装を書き換えても性質は変わらないので、このテストは E (外部仕様テスト) に当たる。

エコシステムにこの種の道具が無かった。あるのは、例にもとづくテストの実行と表示 (std/unittest、nim-power-assert、nim-gherkin-runner)、テストの検出力の測定 (nim-muter)、性質の証明 (nim-z3、ig-verify) である。証明は、式で書ける規則に限られる。式に落ちない実装 (構文解析、組版、ファイル形式) の性質を、入力を多数生成して確かめる層が抜けていた。

もう一つの使い道が nim-muter にある。生き残った変異について、元のコードと変異後で結果が分かれる入力を探して示す (ADR-MUTER-0004 §5)。生成器と縮小は、そこでも要る。

### 参考にしたもの

- QuickCheck (Haskell): 型ごとに生成器と縮小器を書く。縮小器を書き忘れると縮まず、生成器の制約 (並び替え済み、など) を縮小が破ることがある。
- Hypothesis (Python): 値ではなく、値を作るときに引いた乱数の列を縮める。縮めた列から値を作り直すので、生成器の制約は必ず保たれ、型ごとの縮小器が要らない。
- Hedgehog (Haskell)、proptest (Rust)、fast-check (TypeScript): 生成と縮小を一体にする。

## 決定

Hypothesis の方式を採る。生成器は「引き」の列 (`Draws`) から値を作る手続きであり、縮小は引きの列を短く・小さくして、値を作り直す。型ごとの縮小器は持たない。

- 引きは `0 ..< count` の整数で、**小さい引きが単純な値**になるように各生成器を書く (整数は 0 に近いほど、列は短いほど、真偽は偽が単純)。
- 既定の種は固定 (0)。同じ種は同じ値の列を作る。テストは実行のたびに同じ入力で走り、失敗は再現する。種を変えるのは、呼ぶ側が明示したときだけである。
- 性質が例外を上げたら、それは反例である。握りつぶさず、理由として報告する。
- 依存は標準ライブラリだけ。

## 仕様

### 生成

- **GEN-01** `intIn(lo, hi)` は `lo` 以上 `hi` 以下の整数を作る。範囲が 0 を含むなら 0 が、含まないなら 0 に近い端が、最も単純な値である。`lo > hi` はエラーである。
- **GEN-02** `seqOf(element, minLen, maxLen)` は、長さが `minLen` 以上 `maxLen` 以下の列を作る。最も単純な値は、長さ `minLen` で、どの要素も最も単純な列である。
- **GEN-03** `boolean` は偽が、`pick(values)` は先頭が、`stringOf(alphabet, minLen, maxLen)` は長さ `minLen` で先頭の文字だけの文字列が、最も単純な値である。空の `values`・`alphabet` はエラーである。
- **GEN-04** 同じ種からは同じ値の列ができ、別の種からは別の列ができる。
- **GEN-05** `map` は生成した値を変換し、`pair` は二つの生成器の値の組を作る。どちらも縮小の対象になる。

### 実行

- **RUN-01** すべての入力で性質が成り立てば、結果は合格で、試した回数は設定の回数である。
- **RUN-02** 性質が偽を返す入力があれば、結果は不合格で、反例はその性質を偽にする値である。
- **RUN-03** 性質が例外を上げたら不合格で、反例にその例外の文言が理由として付く。
- **RUN-04** 回数が 1 未満、縮小の上限が負の設定はエラーである。

### 縮小

- **SHR-01** 反例は、性質を破る最小の値まで縮む: 「100 未満」に対しては 100、「10 以上の要素が無い」に対しては `@[10]`、「長さ 3 未満」に対しては最も単純な要素 3 つの列。
- **SHR-02** 縮めた反例は、それ自体が性質を破る。反例に付く引きの列から `replay` で同じ値を作り直せる。
- **SHR-03** 生成器の制約は縮小の後も保たれる (`map` で偶数にした値の反例は偶数である)。
- **SHR-04** 縮小は、設定した試行の上限を超えない。上限 0 なら、最初に見つかった反例がそのまま返る。
- **SHR-05** 縮めた反例は極小である: 要素を 1 つ除いても、引きを 1 つ単純にしても、性質は成り立つ。最小とは限らない (「和が 50 未満」に対して、和がちょうど 50 で、除ける要素の無い列が返るが、要素の数が最少とは限らない)。一方を下げて他方を上げるような、二つの引きを同時に動かす縮小はしない。

### 報告と、二つの実装の比較

- **RPT-01** `describe` は、不合格の結果について、反例の値、理由、種、縮小の回数を 1 つの文字列にする。合格の結果については、試した回数を述べる。
- **DIF-01** `distinguish(gen, f, g)` は、`f` と `g` の結果が分かれる入力を探す。分かれなければ合格で、分かれれば最小の入力が反例になる。
- **DIF-02** 例外も結果のうちである。`f` と `g` が同じ型・同じ文言の例外を上げる入力は、分かれていない。片方だけが上げる入力、型か文言の違う例外を上げる入力は分かれていて、理由にはそれぞれが返した値か上げた例外が入る。

  例外を上げただけで反例にする案は採らなかった (2026-10-12 まではそうしていた)。不正な入力で両方が同じように失敗するのは、振る舞いが同じということで、反例にすると、リファクタリングの前後を比べるたびに不正な入力が偽の反例になる。gl-fuzz の `distinguish` (ADR-GFZ-0002) と同じ扱いにした。

## 作らないもの (Future)

- 浮動小数、Unicode の文字列、再帰的な構造の生成器。要る場面が出たら足す。
- 状態機械のテスト (操作の列を生成して不変条件を確かめる)。
- 失敗した種の保存と自動の再実行。種が固定なので、失敗はそのまま再現する。
- カバレッジに導かれた生成 (ファジング)。別の道具の領分である。
